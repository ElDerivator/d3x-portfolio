01 Sistema de identidad y códigos

Respetamos la codificación que ODATA ya construyó. La unidad granular no es la tarea — es la línea: una task_id se descompone en múltiples productos/tareas, cada uno una línea, y se mide por número de línea. El prefijo OBDMX ancla a qué proyecto pertenece.

# Clave de negocio compuesta (business key) — única por línea de trabajo OBDMX-QR03 · <project_code> · <task_id> · L<line_no> # Ejemplo real OBDMX-QR03 · C-1420 · TSK-1042 · L03 │ │ │ │ └─ línea 3 de esa task (un producto/sub-tarea medible) │ │ │ └─ task id (una tarea del WBS) │ │ └─ project code (el proyecto dentro de la obra) │ └─ diferenciador de proyecto (a qué proyecto sigue) └─ prefijo de familia ODATA México

Por qué importa: el avance (físico y financiero), los issues, las estimaciones del GC y las facturas se cuelgan de la línea, no de la tarea. Así una task_id parcialmente instalada reporta % real por producto, y nada se promedia a ciegas. Es la granularidad que hace posible el reporting algorítmico.

04 Pasos de construcción

Orden de build. Todo en una Solution única y reversible del tenant del cliente.

  1. Modelo de datosCrear las 11 tablas, la clave compuesta OBDMX·task·line, choices (dimension, discipline, AWP type) y las relaciones lookup. Reglas de negocio: business_key calculado, aging de issues.
  2. App de captura (Power Apps móvil)Formulario estandarizado: foto + issue + cantidad + geolocalización, ligado a la línea. Offline para campo. Owner obligatorio en cada registro.
  3. Flujos de gate y aprobación (Power Automate)Gate de reconciliación físico-vs-financiero (marca discrepancia), aprobación de facturas, y el bot de ingesta desde correo/WhatsApp.
  4. Portal de GCs (Power Pages)Form autenticado de estimaciones + carga de CFDI, escribiendo a od_gc_estimate y od_invoice con parseo AI Builder.
  5. Tableros (Power BI)Medidas DAX por dimensión: avance físico por sistema, curva-S financiera vs física, issues abiertos por frente. El formato del cliente como query.
  6. Process MiningConectar el event-log de Dataverse (vía OData) para medir cuellos de botella del flujo real. Fase posterior — es el add-on caro.
  7. Capacitación y manualesEntrenamiento por departamento + manuales de operación por rol. Corte para la nueva fase de construcción.
